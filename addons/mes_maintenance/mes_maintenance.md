# 정비 (`mes_maintenance`)

정비 요청부터 완료까지 작업 내용, 소요 시간, 비용을 기록한다.

## 환경
- Odoo 20.0. 설치된 것은 `base`와 `web`뿐이다. 다른 Odoo 앱은 없다.
- 애드온 하나로 만든다. 모듈 이름은 `mes_maintenance`, 의존은 `base`만이다.
- 다른 `mes_` 모듈과 무관하게 혼자 설치되고 동작한다. 다른 모듈의 존재를 가정하지 않는다.
- 회사는 하나라고 가정한다.
- 역할은 세 가지다.
  - **요청자**(현장 작업자): 설비 이상을 신고한다.
  - **정비원**: 배정된 요청을 작업한다.
  - **관리자**(정비 관리자): 요청을 접수·배정하고 설비를 관리한다.
  - 정비원은 요청자가 할 수 있는 일을, 관리자는 정비원이 할 수 있는 일을 모두 할 수 있다.
- 역할은 Odoo 사용자 계정에 부여하는 그룹으로 나눈다. 애드온은 요청자·정비원·관리자 세 그룹을 제공하고, 관리자 그룹은 정비원 그룹을, 정비원 그룹은 요청자 그룹을 포함한다. 각 사람은 자기 계정으로 로그인하고, 그 계정의 그룹에 따라 보이는 메뉴·버튼과 할 수 있는 일이 정해진다.
- 세 그룹 중 어느 것도 없는 사용자에게는 이 애드온의 메뉴가 보이지 않고, 데이터에도 접근할 수 없다.
- `base`와 `web`만으로는 거래처 목록 메뉴가 없다. 외부 업체(거래처) 목록·상세로 가는 메뉴는 이 애드온이 제공한다.
- 화면 문구는 한국어로 쓴다.
- 테스트 코드와 데모 데이터는 넣지 않는다. 설치에 필요한 것(그룹, 번호 매김, 자동 처리 등)만 넣는다.

## 다루는 데이터
- **설비**
  - 코드(중복 불가), 이름, 위치
  - 담당 정비원(정비원 그룹의 사용자)
  - 예방 정비 주기(일, 0이면 예방 정비 없음), 다음 예방 정비 예정일(주기가 0보다 크면 필수)
  - 누적 정비 횟수, 누적 비용
  - 사용 여부
- **정비 요청**
  - 번호: 저장할 때 자동으로 매김. 예: `MR/2026/0001`
  - 설비, 요청자(사용자, 만든 사람), 요청일
  - 유형(고장 정비·예방 정비), 우선순위(보통·높음·긴급)
  - 증상
  - 배정 정비원(정비원 그룹의 사용자), 상태, 반려 사유
  - 작업 기록 목록, 비용 목록
  - 총 소요 시간, 총 비용
- **작업 기록**: 요청마다 여러 개. 작업 일시, 작업자(정비원 그룹의 사용자, 기본값은 입력한 사람), 소요 시간(시간 단위), 작업 내용
- **비용**: 요청마다 여러 개. 항목(부품·외주·기타), 설명, 금액(회사 통화), 외부 업체(거래처, 선택)

## 상태와 흐름

```
요청 → 접수 → 작업 중 → 완료
  ↘ 반려
```

| 동작 | 출발 상태 → 도착 상태 | 누가 | 조건 |
|---|---|---|---|
| 요청 | (새로 만듦) → 요청 | 요청자 이상 | 사용 중인 설비만 고를 수 있다. 예방 정비 요청은 자동 처리가 만든다 |
| 접수 | 요청 → 접수 | 관리자만 | 배정 정비원이 정해져 있어야 한다 |
| 반려 | 요청 → 반려 | 관리자만 | 반려 사유를 입력해야 한다 |
| 작업 시작 | 접수 → 작업 중 | 배정 정비원 또는 관리자 | |
| 완료 | 작업 중 → 완료 | 배정 정비원 또는 관리자 | 작업 기록이 하나 이상 있어야 한다. 예방 정비 요청이면 설비의 다음 예방 정비 예정일을 완료일 + 주기로 갱신한다 |

## 업무 규칙
- 소요 시간과 금액은 음수일 수 없다.
- 상태는 위의 동작으로만 바뀐다. 상태 값을 직접 고쳐서 바꿀 수 없다.
- 설비의 누적 횟수와 누적 비용은 완료된 요청만 센다.
- **수정 범위**
  - 요청 상태: 요청을 만든 요청자 본인과 관리자가 설비·유형·우선순위·증상을 고칠 수 있다.
  - 요청·접수·작업 중 상태: 관리자는 배정 정비원을 바꿀 수 있다. 바꾸면 이전 정비원은 그 요청을 더 이상 작업할 수 없다.
  - 접수·작업 중 상태: 작업 기록과 비용은 배정 정비원과 관리자가 추가·수정·삭제한다.
  - 정비원은 배정되지 않은 요청을 볼 수 있지만 고칠 수 없다.
  - 완료되거나 반려된 요청은 수정할 수 없다(작업 기록·비용 포함).
- **삭제**
  - 요청 상태의 요청만 지울 수 있다. 만든 요청자 본인 또는 관리자가 지운다.
  - 설비는 관리자만 지울 수 있다. 정비 요청이 있는 설비는 지울 수 없고, 사용 중지만 할 수 있다.

## 화면
- 설비 목록·상세. 상세에서 그 설비의 정비 요청 목록으로 이동
- 정비 요청 목록·상세(작업 기록·비용 포함), 칸반(상태별)
- 검색: 내 요청(내가 만든 것), 내게 배정된 요청, 긴급, 상태별, 설비별
- 요청자에게는 정비 요청 메뉴에 자기가 만든 요청만 보인다
- 외부 업체(거래처) 목록·상세. 상세에서 그 업체에 지급한 정비 비용 합계를 본다(완료된 요청의 비용만)
- **반려 사유 입력 화면:** 반려할 때 사유를 묻는 작은 창

## 자동 처리
- 매일 한 번, 사용 중이고 다음 예방 정비 예정일이 오늘 이전인 설비에 대해 예방 정비 요청을 만든다. 같은 설비에 아직 끝나지 않은(완료·반려가 아닌) 예방 정비 요청이 있으면 만들지 않는다.

## 업무 흐름

### 1. 고장 신고부터 수리 완료까지
- **언제:** 현장에서 설비 이상을 발견했을 때
- **어떻게:**
  1. 현장 작업자(요청자)가 정비 요청을 만든다. 설비, 유형(고장 정비), 우선순위(긴급), 증상을 넣는다.
  2. 정비 관리자가 요청 목록에서 확인하고, 정비원을 배정한 뒤 [접수]를 누른다.
  3. 배정된 정비원이 자기 계정으로 "내게 배정된 요청"을 열고 [작업 시작]을 누른다.
  4. 정비원이 작업 기록과 비용을 입력한다. 예: 1.5시간 베어링 교체 / 부품 45,000원, 외주 업체 수리비
  5. [완료]를 누른다.
- **결과:**
  - 총 소요 시간과 총 비용이 계산된다.
  - 그 설비의 누적 정비 횟수와 누적 비용이 늘어난다.
  - 외주 업체(거래처) 화면의 정비 비용 합계에 반영된다.
  - 요청은 더 이상 수정할 수 없다.
  - 요청자는 "내 요청"에서 진행 상태(요청 → 접수 → 작업 중 → 완료)를 볼 수 있다.

### 2. 받지 않을 요청 반려
- **언제:** 같은 고장을 두 번 신고했거나 정비 대상이 아닐 때
- **어떻게:** 정비 관리자가 [반려]를 누르면 사유를 묻는 창이 뜨고, 사유를 적어 확인한다.
- **결과:** 반려 상태가 되고 사유가 남는다. 요청자가 "내 요청"에서 사유를 볼 수 있다.

### 3. 담당 정비원 바꾸기
- **언제:** 배정된 정비원이 자리를 비워 다른 사람이 맡아야 할 때
- **어떻게:** 정비 관리자가 접수되었거나 작업 중인 요청의 배정 정비원을 바꾼다.
- **결과:** 새 정비원의 "내게 배정된 요청"에 나타나고 새 정비원이 작업을 이어 간다. 이미 입력된 작업 기록은 그대로다.

### 4. 예방 정비
- **언제:** 주기적으로 점검해야 하는 설비가 있을 때
- **어떻게:**
  1. 관리자가 설비에 예방 정비 주기(예: 30일)와 다음 예정일을 정한다.
  2. 예정일이 지나면 다음 날 아침 예방 정비 요청이 자동으로 생긴다.
  3. 고장 정비와 같이 접수 → 작업 시작 → 완료한다.
- **결과:**
  - 완료하면 그 설비의 다음 예정일이 완료일 + 30일로 바뀐다.
  - 끝나지 않은 예방 정비 요청이 있으면 새로 생기지 않는다.
  - 사용 중지된 설비에는 생기지 않는다.

### 되면 안 되는 것 (해 보면 거부되어야 함)
- 정비원을 배정하지 않고 [접수] → 거부
- 사유 없이 [반려] → 거부
- 정비원 그룹이 아닌 사람을 정비원(배정 정비원, 설비 담당, 작업 기록 작업자)으로 지정 → 거부
- 배정되지 않은 정비원이 작업 시작·작업 기록·비용·완료를 함 → 거부
- 요청자가 작업 시작·작업 기록·비용·완료를 함 (화면 밖에서 시도해도) → 거부
- 요청자가 다른 사람이 만든 요청을 보거나 고침 → 보이지 않음, 거부
- 접수된 요청의 증상·우선순위를 요청자가 고침 → 거부
- 작업 기록 없이 [완료] → 거부
- 소요 시간이나 금액이 음수 → 거부
- 완료되거나 반려된 요청(작업 기록·비용 포함)을 고침 → 거부
- 요청 상태가 아닌 요청을 지움, 요청이 있는 설비를 지움 → 거부
- 사용 중지된 설비로 새 요청을 만듦 → 거부
- 주기가 0보다 큰데 다음 예정일이 빈 설비를 저장함 → 거부
- 요청자·정비원이 접수·반려·배정 변경을 하거나 설비를 고침 (화면 밖에서 시도해도) → 거부
- 상태 값을 직접 바꿈 (화면 밖에서 시도해도) → 거부
- 같은 설비 코드를 두 번 등록함 → 거부
