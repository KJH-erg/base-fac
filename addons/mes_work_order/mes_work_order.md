# 작업지시 (`mes_work_order`)

작업지시를 만들고 착수부터 완료까지 진행 상태를 관리한다.

## 환경
- Odoo 20.0. 설치된 것은 `base`와 `web`뿐이다. 다른 Odoo 앱은 없다.
- 애드온 하나로 만든다. 모듈 이름은 `mes_work_order`, 의존은 `base`만이다.
- 다른 `mes_` 모듈과 무관하게 혼자 설치되고 동작한다. 다른 모듈의 존재를 가정하지 않는다.
- 회사는 하나라고 가정한다.
- 역할은 두 가지다: **작업자**(현장 작업자), **관리자**(생산 관리자). 관리자는 작업자가 할 수 있는 일을 모두 할 수 있다.
- 역할은 Odoo 사용자 계정에 부여하는 그룹으로 나눈다. 애드온은 작업자·관리자 두 그룹을 제공하고, 관리자 그룹은 작업자 그룹을 포함한다. 각 사람은 자기 계정으로 로그인하고, 그 계정의 그룹에 따라 보이는 메뉴·버튼과 할 수 있는 일이 정해진다.
- 두 그룹 중 어느 것도 없는 사용자에게는 이 애드온의 메뉴가 보이지 않고, 데이터에도 접근할 수 없다.
- 화면 문구는 한국어로 쓴다.
- 테스트 코드와 데모 데이터는 넣지 않는다. 설치에 필요한 것(그룹, 번호 매김, 자동 처리 등)만 넣는다.

## 다루는 데이터
- **작업지시**
  - 번호: 저장할 때 자동으로 매김. 예: `WO/2026/0001`
  - 제목, 대상 품목(글자), 수량
  - 담당자(작업자 그룹의 사용자 한 명)
  - 계획 시작일, 계획 종료일
  - 실제 착수 시각, 실제 완료 시각, 실제 소요 시간(시간 단위, 착수~완료로 계산하며 보류 기간도 포함)
  - 상태, 메모
  - 지연 여부
  - 진행률(완료한 공정 단계의 비율)
- **공정 단계**: 작업지시마다 여러 개. 순서, 단계 이름, 완료 여부, 완료 시각

## 상태와 흐름

```
초안 → 확정 → 진행 중 → 완료
         ↘ 보류 ↗ (진행 중 ↔ 보류)
초안·확정·진행 중·보류 → 취소
```

| 동작 | 출발 상태 → 도착 상태 | 누가 | 조건 |
|---|---|---|---|
| 확정 | 초안 → 확정 | 관리자만 | 수량이 0보다 크고, 계획 시작일·종료일이 있고, 공정 단계가 하나 이상 있어야 한다 |
| 착수 | 확정 → 진행 중 | 담당자 본인 또는 관리자 | 착수 시각을 기록한다 |
| 보류 | 진행 중 → 보류 | 담당자 본인 또는 관리자 | |
| 재개 | 보류 → 진행 중 | 담당자 본인 또는 관리자 | |
| 완료 | 진행 중 → 완료 | 담당자 본인 또는 관리자 | 모든 공정 단계가 완료되어야 한다. 완료 시각을 기록한다 |
| 취소 | 초안·확정·진행 중·보류 → 취소 | 관리자만 | |

## 업무 규칙
- 계획 종료일은 계획 시작일보다 앞설 수 없다.
- 상태는 위의 동작으로만 바뀐다. 상태 값을 직접 고쳐서 바꿀 수 없다.
- **수정 범위**
  - 초안·확정: 관리자가 모든 항목과 공정 단계(추가·삭제·순서·이름)를 고칠 수 있다.
  - 진행 중·보류: 관리자는 계획 종료일과 담당자만 고칠 수 있다. 공정 단계는 추가·삭제할 수 없다.
  - 메모는 완료·취소 전까지 담당자 본인과 관리자가 고칠 수 있다.
  - 완료되거나 취소된 작업지시는 아무것도 고칠 수 없다.
- **공정 단계 완료 표시**
  - 진행 중일 때만 할 수 있다. 표시하면 그 시각을 기록한다.
  - 진행 중일 때는 완료 표시를 되돌릴 수 있다. 되돌리면 완료 시각이 지워진다.
- **지연**
  - 자동 처리가 지연으로 표시한다.
  - 작업지시가 완료·취소되거나 계획 종료일이 오늘 이후로 바뀌면 지연 표시가 풀린다.
- **삭제:** 초안 상태의 작업지시만 관리자가 지울 수 있다.

## 화면
- 작업지시 목록, 상세(공정 단계 포함), 칸반(상태별)
- 검색: 내 작업지시, 지연, 상태별
- 상세 화면의 상태 버튼(확정, 착수, 보류, 재개, 완료, 취소)
- **일괄 담당자 지정:** 목록에서 여러 작업지시를 골라 담당자를 한 번에 바꾸는 화면이다. 완료·취소되지 않은 작업지시만 대상이 되고, 새 담당자는 작업자 그룹의 사용자여야 한다.

## 자동 처리
- 매일 한 번, 계획 종료일이 지났는데 완료·취소되지 않은 작업지시를 지연으로 표시한다.

## 업무 흐름

### 1. 작업을 내리고 끝내기 (평상시)
- **언제:** 생산 관리자가 이번 주 작업을 현장에 내릴 때
- **어떻게:**
  1. 관리자가 작업지시를 만든다. 제목, 품목, 수량, 담당 작업자, 계획 기간, 공정 단계(예: 절단 → 용접 → 검사)를 넣는다.
  2. [확정]을 누른다.
  3. 담당 작업자가 자기 계정으로 로그인해 "내 작업지시"에서 그 작업지시를 열고 [착수]를 누른다.
  4. 작업하면서 공정 단계를 하나씩 완료로 표시한다.
  5. 모든 단계가 끝나면 [완료]를 누른다.
- **결과:**
  - 착수 시각과 완료 시각이 기록되고, 실제 소요 시간이 계산된다.
  - 진행률이 단계마다 올라간다(33% → 67% → 100%).
  - 칸반에서 완료 열로 옮겨지고, 이후에는 수정할 수 없다.

### 2. 잠시 멈췄다가 다시 하기
- **언제:** 자재가 모자라거나 설비가 멈춰 작업을 잠시 멈춰야 할 때
- **어떻게:** 담당 작업자가 [보류]를 누르고 메모에 사유를 적는다. 문제가 풀리면 [재개]를 누른다.
- **결과:**
  - 보류 동안에도 완료한 공정 단계와 착수 시각은 그대로다.
  - 보류 중에는 공정 단계를 완료로 표시할 수 없다.
  - 재개하면 다시 진행 중이 된다.

### 3. 늦어진 작업을 다른 사람에게 넘기기
- **언제:** 계획 종료일이 지났는데 끝나지 않은 작업이 있을 때
- **어떻게:**
  1. 다음 날 아침 자동 처리가 그 작업지시를 지연으로 표시한다.
  2. 관리자가 "지연" 검색으로 모아 보고, 여러 건을 골라 [일괄 담당자 지정]으로 다른 작업자에게 넘긴다.
  3. 필요하면 관리자가 계획 종료일을 늦춘다.
- **결과:**
  - 새 담당자의 "내 작업지시"에 나타나고, 새 담당자가 착수·완료할 수 있다. 이전 담당자는 더 이상 착수·완료할 수 없다.
  - 계획 종료일을 오늘 이후로 늦추면 지연 표시가 풀린다.

### 4. 필요 없어진 작업 취소
- **언제:** 주문이 취소되어 작업이 필요 없어졌을 때
- **어떻게:** 관리자가 [취소]를 누른다.
- **결과:** 취소 상태가 되고 수정할 수 없다. 지연 표시도 풀린다. 작업자 화면에는 [취소] 버튼이 없다.

### 되면 안 되는 것 (해 보면 거부되어야 함)
- 공정 단계가 남아 있는데 [완료]를 누름 → 거부, 남은 단계를 알려 줌
- 공정 단계가 없거나 수량이 0이거나 계획 기간이 없는데 확정함 → 거부
- 작업자가 작업지시를 만들거나 고치거나 확정하거나 지움 (화면 밖에서 시도해도) → 거부
- 담당자가 아닌 작업자가 착수·보류·재개·완료나 공정 단계 완료 표시를 함 → 거부
- 진행 중이 아닌 작업지시의 공정 단계를 완료로 표시함 → 거부
- 진행 중·보류인 작업지시에 공정 단계를 추가하거나 지움 → 거부
- 작업자가 취소나 일괄 담당자 지정을 함 (화면 밖에서 시도해도) → 거부
- 작업자 그룹이 아닌 사용자를 담당자로 지정함 (일괄 담당자 지정 포함) → 거부
- 완료되거나 취소된 작업지시를 고치거나 일괄 담당자 지정에 넣음 → 거부
- 초안이 아닌 작업지시를 지움 → 거부
- 상태 값을 직접 바꿈 (화면 밖에서 시도해도) → 거부
- 계획 종료일이 시작일보다 앞서게 저장함 → 거부

## 역할별 기능

| 기능 | 작업자 | 관리자 |
|---|---|---|
| 작업지시 목록·상세·칸반 조회, 검색 | 가능 | 가능 |
| 작업지시 생성, 초안·확정 상태에서 수정, 공정 단계 편성 | – | 가능 |
| 진행 중·보류 상태에서 계획 종료일·담당자 변경 | – | 가능 |
| 초안 작업지시 삭제 | – | 가능 |
| 확정 | – | 가능 |
| 메모 수정 | 본인 담당 작업지시만 | 가능 |
| 공정 단계 완료 표시·되돌리기 | 본인 담당 작업지시만 | 가능 |
| 착수, 보류, 재개, 완료 | 본인 담당 작업지시만 | 모든 작업지시 |
| 취소 | – | 가능 |
| 일괄 담당자 지정 | – | 가능 |
